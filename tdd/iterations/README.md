# 迭代记录规范

本目录记录每一轮 TDD 迭代的完整过程。每轮迭代一个文件，编号递增，永不删除。

## 命名约定

```
{NNN}_{简短主题}.md
```

- **NNN**：三位递增编号，从 000 开始
- **简短主题**：snake_case，描述本轮迭代的核心目标

示例：`001_initial_baseline.md`, `002_avgpool_coverage.md`, `003_add_renderer.md`

## 文件格式

每个迭代文件必须包含以下章节：

```markdown
# 迭代 {NNN}: {主题}

## 基本信息
- **日期**: YYYY-MM-DD
- **前置迭代**: {上一轮编号}
- **触发来源**: {人类需求 / 测试缺口发现}

## 目标
本轮迭代要解决什么问题、覆盖什么能力。

## 新增/修改的测试用例
列出本轮新增或修改预期的用例。

## 执行结果
首次执行的结果（预期失败的记录）。

## 代码修改
本轮为了让测试通过而做的代码修改摘要。

## 最终结果
全量回归执行结果。

## 发现与后续
本轮发现的新问题、新缺口、对后续迭代的建议。
```

## 编写时机

- **迭代开始时**：填写基本信息、目标、新增用例
- **首次执行后**：填写执行结果
- **代码修改后**：填写代码修改摘要
- **全量回归后**：填写最终结果和发现
