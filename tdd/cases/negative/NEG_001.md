# NEG_001: float32 无 Q/DQ 模型拒绝

## 验证目标

验证代码生成器在接收到不包含量化信息的 float32 ONNX 模型时，能正确拒绝并给出明确错误信息，而不是崩溃或静默产出错误代码。

## 网络结构

```
Input(FLOAT32) → Conv(kernel=3×3) → Relu → Output(FLOAT32)
```

注意：此模型无 QuantizeLinear / DequantizeLinear 节点。

## 输入

- **张量形状**: `[1, 3, 8, 8]`（NCHW）
- **数据类型**: float32

## 算子参数

| 算子 | 参数 |
|------|------|
| Conv | kernel=[3,3], stride=[1,1], pads=[1,1,1,1], group=1, weight shape=[8,3,3,3], dtype=float32 |
| Relu | 标准 Relu |

## 量化设计

无量化。所有张量为 float32。

## 预期结果

- **codegen status**: `unsupported`
- **pipeline 退出码**: 非零
- **关键验证点**: 错误信息中应包含"非 int8 Q/DQ 模型"或类似说明；不产出 model.c；不崩溃（无未捕获异常）

## 边界/风险

- 这是最常见的"用户错误"场景：拿着未量化的模型喂给代码生成器
- 代码生成器必须在 pipeline 早期（converter 阶段或 codegen 入口）明确拒绝
- 如果拒绝逻辑不完整，可能走到 codegen 内部后因缺少量化字段而崩溃
